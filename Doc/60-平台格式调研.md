# 平台格式调研

> 状态：**调研框架 + 待验证清单**。本文不得凭印象填写结论；所有结论必须由 M1/M2 实测支撑，并标注状态与证据。
> 最后更新：2026-10-12

## 0. 调研方法与记录要求

1. **状态三态标记**（禁止把推测写成结论）：
   - `已验证`：有样本 + 工具输出 + 真机结论支撑；
   - `推测（待验证）`：基于公开资料的推断，需 M1/M2 验证；
   - `不适用`：该平台无此概念。
2. **每条结论必须可复现**：记录命令、工具版本、样本指纹（hash 前 8 位）、关键输出片段，归档到 `Doc/evidence/<platform>/`。
3. **样本驱动**：先拿到样本再下结论；不同机型/系统版本分别记录，不得用单一机型代表整个平台。
4. **结论回填**：M2 结束时，本文所有 `推测` 项应被更新为 `已验证` 或 `不适用`。

### 通用调研维度

| 维度 | 说明 |
| --- | --- |
| 存储形态 | 单文件容器（静态图内嵌视频）/ 双文件 / 媒体库内部配对 |
| 静态帧 | 格式（JPEG/HEIC）、分辨率、EXIF 项 |
| 动态视频 | 容器、编码、分辨率、帧率、时长上限 |
| 关联机制 | 靠文件系统命名、媒体库记录、还是文件内元数据 |
| 静止帧时刻 | 是否显式标记 |
| 元数据 | 拍摄时间、时区、GPS、方向、设备信息存放在哪一侧 |
| 导出通道 | 真机可拿到的文件是原始件还是二次编码件 |
| 导入通道 | 外部生成的组合能否被识别为动态照片 |
| 机型差异 | 同平台不同厂商/机型的实现差异 |

## 1. iOS（Live Photo / 实况照片）

| 维度 | 结论 | 状态 |
| --- | --- | --- |
| 组成 | 一张静态图 + 一段配对短视频 | 已验证（高置信，M1 复核） |
| 关联机制 | 静态图与视频中携带同一关联标识（Content Identifier），系统据此配对 | 推测（待验证）：字段名与位置需以导出件实测确认 |
| 静止帧时刻 | 视频中有"静止帧时刻"标记，指明静态图对应视频哪一帧 | 推测（待验证） |
| 时长上限 | 约 3 秒量级，超出部分需裁剪 | 推测（待验证）：需实测系统接受的上限与超限时行为 |
| 编码/容器 | HEVC 或 H.264，QuickTime 容器 | 推测（待验证）：需确认 iOS 当前版本接受的编码组合 |
| 静态图格式 | HEIC（高效模式）或 JPEG | 推测（待验证） |
| 导出通道 | 通过系统相册/同步导出可得到原始静态图与视频文件 | 推测（待验证）：需确认导出的是否为未修改原件 |
| 导入通道 | **关键未知项**。候选：macOS 照片同步、iCloud、第三方工具、快捷指令、自建宿主 App（PhotoKit 写入配对资源） | 未验证（M1 重点） |
| 机型/版本差异 | 不同 iOS 版本行为可能变化 | 未验证 |

### 待验证问题清单

- V1：导出件中关联标识的确切字段与位置，以及可写入它的工具（exiftool / ffmpeg / 其他）。
- V2：静止帧时刻标记的格式与写入方式。
- V3：iOS 各版本接受的编码/容器/分辨率/帧率组合矩阵。
- V4：时长上限的确切值与超限行为（截断还是整体不识别）。
- V5：导入通道候选的实际可用性（M1 逐条实测，至少保底一条）。
- V6：静态图与视频的分辨率/宽高比不一致时是否被接受。
- V7：方向（EXIF orientation / 视频旋转矩阵）如何处理才正确。
- V8：是否必须 HEIC，JPEG 是否同样被接受。

## 2. HarmonyOS / 鸿蒙（动态照片）

| 维度 | 结论 | 状态 |
| --- | --- | --- |
| 存储形态 | 未知。可能为上报表单文件容器（静态图内嵌视频）或系统媒体库中的双资源 | 未验证（M1 重点） |
| 静态帧 | 未知（JPEG / HEIC） | 未验证 |
| 动态视频 | 未知（容器、编码、时长、分辨率） | 未验证 |
| 关联机制 | 未知（文件内偏移/元数据，或媒体库记录） | 未验证 |
| 时长上限 | 未知（需确认是否与 iOS 一致） | 未验证 |
| 官方 API | 系统图库/媒体库 API 可能提供动态照片对象并分别给出图片与视频 | 推测（待验证） |
| 导出通道 | 候选：hdc 文件拉取、USB 传输、图库分享/导出 | 未验证（M1 重点） |
| 机型差异 | 不同机型/系统版本可能不同（鸿蒙 7 与其它版本、不同 OEM） | 未验证 |

### 待验证问题清单

- H1：鸿蒙 7 真机上的动态照片实际存储形态（单文件 / 双文件 / 媒体库内部）。
- H2：若为单文件容器，视频数据的定位方式（内嵌段标识 / 尾部追加 / 多图格式）与偏移字段。
- H3：能否通过官方 API 直接分别取得静态图与视频（优先于逆向容器）。
- H4：hdc 或其它通道能否拿到**原始**文件（未被二次转码）。
- H5：时长、分辨率、编码的实际取值范围，与 iOS 约束的差距。
- H6：静止帧对应视频哪一时刻，是否有显式标记。
- H7：机型/系统版本矩阵内的差异点。
- H8：拍摄时间、GPS、方向等元数据存放位置。
